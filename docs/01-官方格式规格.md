# 01 · official（官方）谱面格式规格

> 来源：Lchzh Docs《Phigros 谱面格式说明》与《相关计算》《实测数据》（<https://docs.lchzh.top/learning/phigros/>）、Phira 官方格式解析实现（`prpr/src/parse/pgr.rs`），并用本仓库 `packages/白复生 AT（official格式）` 实测校验。
> 标记同 `格式说明.md`：`[实测]` 已由样本数据验证，`[文档]` 来自参考文档，`[未验证]` 待确认。

---

## 1. 单位与常量

| 名称 | 定义 | 1920×1080 下的值 | 用于 |
| --- | --- | --- | --- |
| `W` / `H` | 画面宽度 / 高度 | 1920 / 1080 px | — |
| `X` | `0.05625 W` | 108 px | `Note.positionX` |
| `Y` | `0.6 H` | 648 px | `Note.floorPosition`、速度事件值 |
| `T` | `1.875 / bpm` 秒 = 1/32 拍 = 128 分音符 | 174 BPM 时 0.010776 s | `time`、`holdTime`、事件时间 |
| `px` | 像素 | — | 线宽等实测值 |

换算：

```
秒 = time × 1.875 / bpm      （[实测]：bpm 174、time 256 → 2.7586 s）
time = 秒 × bpm / 1.875
```

`[文档][实测]`

## 2. 根结构 root

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `formatVersion` | int | 格式版本。目前可用值为 **1** 和 **3**，该值只影响**判定线移动事件**的坐标读取方式。`[文档]` |
| `offset` | float | 谱面偏移，单位**秒**。非负数时音乐立即开始、谱面延迟 \|offset\| 秒开始（等价于 `谱面时间 = 音乐时间 − offset`）。官谱从未出现负数 offset。`[文档]` |
| `judgeLineList` | Array&lt;JudgeLine&gt; | 判定线列表。 |

**已移除的历史字段** `[文档]`：`numOfNotes`（v2.5.0 起移除，音符总数改为实时计算）。读取旧谱时应当忽略它而不是依赖它。

### 2.1 `formatVersion` 与坐标读取

| 版本 | 坐标原点 | 右上角坐标 | 事件值含义 |
| --- | --- | --- | --- |
| 1 | 屏幕左下角 | (880, 520) | 位置被压缩进单个整数：`v = 1000·x + y`（x 取整到 0–880 的整数部分，y 取 `v % 1000`）；`[文档]` Phira 实现：`x = (v − v % 1000)/1000` 后归一化 `(-880 + 2x)/880`，`y = (v % 1000)` 后归一化 `(-520 + 2y)/520` |
| 3 | 屏幕左下角 | (1, 1) | `start`/`end` = x（0–1），`start2`/`end2` = y（0–1）。Phira 归一化为 `-1 + 2·v` |
| 其它 | 屏幕中心 | 单位长度 `0.1 H`（两轴同单位） | `start/end` = x，`start2/end2` = y `[文档]`；Phira 直接报错不支持 `[文档]` |

`[实测]` 本仓库官方样本 `formatVersion = 3`：移动事件的 x ∈ [−0.8, 1.8]、y ∈ [−2, 5]（可以离开屏幕），样本开头 x = 0.5 即屏幕水平中心、y = 0.5 即垂直中心，与「左下角为原点、右上角 (1,1)」的规则吻合（若按「屏幕中心为原点」解释，则 0.5 会是半屏偏移，与谱面实际居中不符）。

## 3. 判定线 JudgeLine

| 字段 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- |
| `bpm` | float | BPM | 决定该判定线的时间单位 `T`。不能为 0 或负数。 |
| `notesAbove` | Array&lt;Note&gt; | — | 从线的**正面**下落（上方）的音符。 |
| `notesBelow` | Array&lt;Note&gt; | — | 从线的**背面**下落（下方）的音符。 |
| `speedEvents` | Array&lt;SpeedEvent&gt; | — | 下落速度事件（单位 Y/s）。 |
| `judgeLineMoveEvents` | Array&lt;JudgeLineEvent&gt; | — | 移动事件（x、y）。 |
| `judgeLineRotateEvents` | Array&lt;JudgeLineEvent&gt; | 度 | 旋转事件，**逆时针为正**。 |
| `judgeLineDisappearEvents` | Array&lt;JudgeLineEvent&gt; | 0–1 | 不透明度事件（≤0 全透明，≥1 不透明）。 |

**已移除的历史字段** `[文档]`：`numOfNotes`（= notesAbove + notesBelow 长度）、`numOfNotesAbove`、`numOfNotesBelow`（v2.5.0 起移除；读取时不会使用这些属性）。

**事件列表规范**（不满足会导致游戏卡死/异常，见 `格式说明.md` §8）：

- 除速度事件外，第一条事件 `startTime` 为极小哨兵值（`[实测]` 官谱用 `-999999`），速度事件第一条 `startTime` 为 `0`。
- 最后一条事件 `endTime` 为极大哨兵值（`[实测]` 官谱用 `1000000000`）。
- 相邻事件的 `startTime` 等于上一条的 `endTime`（首尾相接）。
- 事件列表**不能是空数组**。

`[实测]` 官方样本 24 条判定线的字段是「扁平」布局（没有 `eventLayers`/`extended`/`name`/`texture`），即当前游戏官谱只使用上述 7 个字段。

## 4. 音符 Note

| 字段 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- |
| `type` | int | — | 音符类型，见下表。其他值表现为「不可见也不可判定」。 |
| `time` | int | `T` | 判定时刻。 |
| `positionX` | float | `X` | 沿判定线方向、相对线中心的水平位置。值为 1 时常用于「时钟」效果。 |
| `holdTime` | int | `T` | 长按时间。非 Hold 音符恒为 0；Hold 为 0 时音符不可见（官谱恒 > 0）。即使写成 `0.0` 之类，游戏仍按整数读取。 |
| `speed` | float | 倍率 | 音符速度倍率。**对 Hold：头部速度倍率恒为 1，此值表示 Hold 尾的速度倍率**。 |
| `floorPosition` | float | `Y` | 音符判定时距判定线的垂直位置，应当等于判定线在 `Note.time` 时的垂直位置 `PJ(tN)`。游戏**会重新计算**而不直接使用该值（旧版本速度事件里同名字段亦同）。 |

**类型编号** `[文档][实测]`：

| 值 | 类型 | 玩家操作 |
| --- | --- | --- |
| 1 | Tap | 在判定时刻点击 |
| 2 | **Drag** | 判定时刻手指位于判定区域内（无需点击） |
| 3 | **Hold** | 判定时刻点击并长按至音符消失 |
| 4 | Flick | 判定时刻向任意方向滑动 |

Hold 长度（单位 Y）：`d = η · tH · 1.875 / bpm`，其中 `η = speed`（尾速度）、`tH = holdTime`。官方设计惯例：`η` 应等于判定线在判定时刻的实时速度 `VJ(tN)`，这样打击前后 Hold 尾速度连续。`[文档]`

## 5. 速度事件 SpeedEvent

| 字段 | 类型 | 单位 | 说明 |
| --- | --- | --- | --- |
| `startTime` | int | `T` | 开始时刻（第一条应为 0）。 |
| `endTime` | int | `T` | 结束时刻。 |
| `value` | float | `Y/s` | 该时间段内的判定线速度（线性时间段，值为常量）。 |

**已移除字段**：`floorPosition`（formatVersion 3 旧版有，表示事件开始时刻的垂直位置；游戏不读取而是实时计算）。

约定用法 `[实测]`：

- `value = 0`：判定线停止，note 冻结（`[实测]` 样本中 196 处）。
- `value = 999`：瞬移/无限远（样本末段 `[14400, 1000000000] value = 999`，让谱面结束后音符永不到线）。
- `value < 0`：note 反向运动（向上飞）。
- 常规值形如 1、1.1、1.65、2.2、6.6 等。
- 判定线实时速度 `VJ(t) = vk`；垂直位置 `PJ(t) = pk + vk · (t − tk) · 1.875 / bpm`（见 `docs/03-渲染与数学.md`）。

`[实测]` 样本速度事件统计：1262 条，`value ∈ {−1.1, −0.628, …, 0, 0.074, …, 999}`，`startTime ∈ [0, 14400]`。

## 6. 判定线事件 JudgeLineEvent

| 字段 | 类型 | 适用事件 | 说明 |
| --- | --- | --- | --- |
| `startTime` / `endTime` | int | 全部 | 单位 `T`。 |
| `start` / `end` | float | 全部 | 起始/结束值。 |
| `start2` / `end2` | float | 移动（v3） | y 坐标；v3 中 x 用 `start/end`。 |

- **消失事件**：`start`/`end` 为不透明度，≤0 全透明、≥1 不透明，中间线性插值。`[文档][实测]` 样本取值范围 `[0, 1]`。
- **移动事件**：v3 为 `start/end` = x、`start2/end2` = y（左上角原点 → 归一化 0–1）；v1 为压缩整数（见 §2.1）。
- **旋转事件**：`start`/`end` 为逆时针角度（度）。`[实测]` 样本取值范围 `[-2130, 1530]`。
- v2.5.0 之前，消失与旋转事件也带 `start2/end2`（恒为 0，无意义）；v2.5.0 及以后不再包含。`[文档]`

## 7. 事件规范化规则（解析器必须实现）

按 Lchzh Docs《实测数据》`[文档]`：

1. 事件按 `startTime` 升序排序后使用。
2. 速度事件列表若第一条 `startTime ≠ 0`，其 floorPosition 计算为 `startTime / bpm × 1.875`（等价于在其前插入一条 `[0, startTime] value = 1` 的事件）。
3. 与上一事件**相离**（有空隙）：在该空隙内做解析延拓（按斜率外推）。
4. 与上一事件**相交**：相交部分被忽略——即把 `startTime` 改为上一事件的 `endTime`，保持 `end`/`end2` 与斜率不变地重算 `start`/`start2`。
5. `startTime >= endTime` 的事件被忽略。
6. 读取到重复 JSON 键时**取第一个**（与 JavaScript `JSON.parse` 取最后一个的行为不同）。
7. 浮点精度为 float32；数字支持科学计数法；`int` 字段遇小数会截断（非四舍五入）。
8. 所有字段都有默认值（int=0、float=0.0、Array=[]、Object={}），但默认值产生的结果**不保证是合法谱面**，因此编辑器保存时应显式写全。

Phira 的实现额外做了两件事 `[文档]`：解析时把 `startTime` 为负的事件时间截到 0（`(e.start_time * r).max(0.)`），并对 `notesAbove`/`notesBelow` 分别按 `time` 排序（`sort_by_key`）。
