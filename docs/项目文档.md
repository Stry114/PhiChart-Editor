面向接手本项目的开发者与代码阅读工具。内容涵盖架构、目录、内部模型契约、核心 API、数据流、测试与开发约定。

上手顺序：§1 项目概览 → §2 目录结构 → §3 架构 → §4 内部模型契约 → §5 关键 API → §6 数据流。仅需先运行项目时，参见 §10 的 `tools/dev_server.py`。

- 编辑器面向用户的操作说明见 [谱师文档.md](谱师文档.md)。

## 1. 项目概览

PhiChart Editor 是 Phigros 谱面的**制谱器与渲染器**：读取 official（游戏本体）与 RPE（Re:PhiEdit）两种谱面格式，在浏览器里实时预览与编辑，并写回两种格式或保存为本编辑器的项目文件。同一套内核提供两个入口（编辑器 / 播放器）。

在线地址（首选使用方式）：**<https://stry114.github.io/PhiChart-Editor/>** —— 每次推送到 `main` 由 GitHub Actions 自动发布；本地开发 / 离线使用见 §10 的 `tools/dev_server.py`。

技术约束：

| 约束 | 说明 |
| --- | --- |
| 零构建 | 全部是原生 ES 模块，直接由浏览器加载；没有打包步骤、没有 `node_modules` 运行时依赖 |
| 零第三方运行时依赖 | zip、gzip、缓动、贝塞尔、PNG 采样等全部自己实现或使用平台 API（`CompressionStream` / `DecompressionStream`） |
| 纯静态部署 | 推到 GitHub Pages 即可运行；`.github/workflows/pages.yml` 已配置白名单部署（只发布四个入口页面 + 样式 + `src/` + `assets/` + `LICENSE` 并写 `.nojekyll`；其余目录不进站点） |
| 分层 | 内核（`src/core`）→ 渲染（`src/render`）→ 应用（`src/app`、`src/editor`、`src/start`），依赖方向单向 |

许可：本项目以 **GPL-3.0** 发布（见仓库根 `LICENSE`）。实现参考的外部项目与其许可见 [Phigros文档.md §8](Phigros文档.md)。

## 3. 架构

### 3.1 分层与依赖方向

```
src/start ─┐
src/app  ──┼─→ src/render ─→ src/core
src/editor ┘        ↑
                 src/ui（图标、跨页交接）
```

- `src/core` 不引用 DOM、Canvas 与 `window`（`sanitize.js`、`zip.js` 使用平台 API 时做了能力检测）；
- `src/render` 只依赖 `src/core` 与浏览器 Canvas API；
- 应用层负责装配、事件接线与状态持久化。

这条边界的用途：内核可作为「函数式预览内核」被任意调用，也可在 Node 下无头测试。

### 3.2 内核的四层结构

| 层 | 职责 | 关键实现 |
| --- | --- | --- |
| 模型层 | 表示谱面（拍值、取值、缓动参数、原始字段） | `model.js` 的 `createChart` / `prepareChart` |
| 编译层 | 把源数据编译成运行期可快速求值的派生数据 | `events.js` 的 `compileEventList` / `compileLayers` / `compileExtended`、`refreshLine()` |
| 求值层 | 给定时刻算出每帧状态（纯函数） | `state.js` 的 `createState` / `evaluate` / `worldTransform` |
| 判定层 | 自动游玩与真实游玩的判定、计分 | `state.js` 的 `advanceJudging` / `advancePlayJudging` / `commitJudgement` |

**源数据与派生数据严格分离**：渲染读的是派生数据（编译后的关键帧、`timeSec` / `durationSec` / `height`），编辑器改的是源数据。改完必须调用局部重编译，否则「时间轴变了、预览没变」。

### 3.3 事件求值模型

- 普通事件（`x` / `y` / `rotate` / `alpha` / `speed`）：`line.layers[]`，每层每键一份事件数组；**多层求和**，只有含该事件的层参与；全空取默认值（`x=y=rotate=0`、`alpha=0`、`speed=1`）。
- 扩展事件（`scaleX` / `scaleY` / `color` / `z` / `theta`）：**不分层**，每条线每键一份（`line.extended[key]`）；不参与求和，未覆盖时间取 `EXTENDED_DEFAULTS`。
- 谱面相机（`x` / `y` / `z` / `angle`）：**谱面级**，每键一份关键帧（`chart.camera[key]` → `chart.cameraRt`）；每帧求值成 `state.camera`，供（伪）3D 投影使用（缺省 `{0,0,0,≈53.13°}` = 默认视图）。
- 判定线高度 `PJ(t)`：速度事件对**秒**积分（`events.js` 的 `buildHeightFn` / `integrateSegment`）。

每层每键的事件在编译期变成按秒排序的 `{t0,t1,v0,v1,f,instant}` 列表，运行期二分查找 + 缓动插值。判定线高度用分段积分并在段末显式取 `t1 − ε`：用 `t === t1` 判断会因浮点 ulp 把下一段的速度采进来。

## 4. 内部模型契约

### 4.1 规范单位

以 `src/core/units.js` 为准：

| 量 | 内部单位 |
| --- | --- |
| 时间（模型层） | 拍 |
| 时间（运行期） | 秒 |
| 音符横向位置 | 官方 X 单位（`1 X = 0.05625 × 画面宽`） |
| 纵向距离与判定线速度 | 官方 Y 单位（`1 Y = 0.6 × 画面高`），速度单位 Y/s |
| 判定线位置 | 以画面中心为原点的比例偏移（x 相对画面宽、y 相对画面高，y 向上为正） |
| 旋转 | 弧度，逆时针为正 |
| 不透明度 | 0–1 |
| 音符类型 | `'tap' \| 'drag' \| 'hold' \| 'flick'` |
| （伪）3D 的 `z` | 画面高比例，正 = 往屏幕内（RPE 写出时长 × 900） |
| （伪）3D 的 `theta` | 弧度，正 = 下落面向屏幕内倾（RPE 写出时转角度制，不取反） |
| 谱面相机 `x` | 画面宽比例（RPE 写出时长 × 1350） |
| 谱面相机 `y` / `z` | 画面高比例（RPE 写出时 × 900） |
| 谱面相机 `angle`（视角） | 弧度，缺省 `PSEUDO3D.ANGLE_DEFAULT ≈ 53.13°`（RPE 写出时转角度制） |
| Hold 长度口径 `holdSpeed` | 枚举 `'own'`（独立尾速度，official 口径）\| `'line'`（跟随判定线速度，RPE/Phira 口径，**缺省**） |
| 全局流速控制 `meta.speedMultiplier` | 无量纲倍率，缺省 1、上限 100（`meta.js` 的 `speedMultiplierOf()` 负责钳制；非法值退回 1） |

**改动模型或解析器时不要新增第二套单位**：换算只发生在 `parse-*.js` / `serialize-*.js`。

### 4.2 chart 对象

`prepareChart(raw)` 的产物（编辑器与播放器的唯一真值）：

```
chart
├─ format            'official' | 'rpe' | 'unknown' | 'project'
├─ source            原始来源信息（formatVersion / rpeVersion / xybind / projectVersion …）
├─ meta              元数据（name / composer / charter / illustrator / level / id / song / background / offset / speedMultiplier）
├─ timing            { bpmList, bpmFactor }
├─ camera            谱面相机关键帧：`{ x:[], y:[], z:[], angle:[] }`（谱面级，与扩展事件同构）
├─ cameraRt          编译后的相机关键帧（每帧求值成 state.camera）
├─ cameraRaw         RPE 根节点 `camera` 里未识别的字段（导出时写回）
├─ lines[]           判定线
│   ├─ id / name / group / groupName / zOrder / isCover / texture / isGif
│   ├─ father / rotateWithFather / bpm / bpmFactor / bpmList
│   ├─ layers[]      事件层：`{ x:[], y:[], rotate:[], alpha:[], speed:[] }`
│   ├─ extended      已实现的扩展事件：`{ scaleX:[], scaleY:[], color:[], z:[], theta:[] }`
│   ├─ extendedRaw   未实现扩展键的原样数据
│   ├─ notes[]       源音符（拍值层）
│   ├─ raw           未建模的原始字段（导出时写回）
│   └─ rt            运行期派生数据
│       ├─ timeline      拍 ↔ 秒换算
│       ├─ x/y/rotate/alpha/speed   编译后的层列表数组
│       ├─ extended      编译后的扩展事件（color 为 `{channels:[...]}`）
│       ├─ heightAt(t)   判定线高度积分函数
│       └─ notes[]       编译后的音符（timeSec / durationSec / height / src）
├─ notes[]           全部音符的扁平列表（按时间排序）
├─ endTime / duration / noteCount
├─ warnings[]        解析告警
├─ diagnostics       { summary, messages }
└─ dropped           { lines, notes, events } 被丢弃的脏数据计数
```

### 4.3 事件与音符字段

| 对象 | 字段 |
| --- | --- |
| 事件（模型层） | `startBeat` / `endBeat` / `start` / `end` / `easingFn` / `easingType` / `easingPreset` / `bezierPoints` / `easingLeft` / `easingRight` |
| 事件（编译后） | `{ t0, t1, v0, v1, f, instant }` |
| 扩展事件 | 同上；`color` 的 `start` / `end` 为 `[r,g,b]`（0–255 整数），编译结果为 `{ channels: [c0,c1,c2] }`；`z` 为画面高比例（正 = 往屏幕内）、`theta` 为弧度（正 = 下落面向屏幕内倾） |
| 相机关键帧 | 与扩展事件同构（`chart.camera[key]`）；`x` 为画面宽比例，`y` / `z` 为画面高比例，`angle`（视角）为弧度（缺省 ≈53.13°） |
| 音符 | `type` / `startBeat` / `endBeat` / `positionX` / `above` / `speed` / `holdSpeed` / `alpha` / `size` / `yOffset` / `visibleTime` / `isFake` / `hitsound` / `tint` / `judgeArea` / `raw` |
| 音符（编译后） | 上述字段 + `lineId` / `timeSec` / `endSec` / `durationSec` / `height` / `tailHeight` / `src` / 判定状态（`judged` / `judgement` / `hitFxTime` / `holdPending`） |

> `height` / `tailHeight` 只在编译后的副本上（`src` 指回源对象），导出器需要高度时用 `line.rt.heightAt(秒)` 现算。

**Hold 的几何有两种口径**（`note.holdSpeed`，见 [Phigros文档.md §4.2](Phigros文档.md)）：

| 口径 | 头部 | 尾部 |
| --- | --- | --- |
| `'own'`（official） | 不乘 `speed`（官方头速度恒为 1） | 头部 + `speed × 时长`；命中后 = `speed × 剩余秒数` |
| `'line'`（RPE / Phira，缺省） | `speed × (PJ(tN) − PJ(t))` | `speed × (PJ(endSec) − PJ(t))`，命中前后**同一公式**（贴线瞬间长度连续） |

### 4.4 每帧状态

`createState(chart)` 的 `state.lines[i]` 由 `evaluate(state, t)` 每帧写入：

| 字段 | 含义 |
| --- | --- |
| `x` / `y` / `rotate` / `alpha` | 线自身变换（比例偏移、弧度、0–1） |
| `height` | 判定线高度 `PJ(t)`（Y） |
| `worldX` / `worldY` / `worldRotate` | 叠加父线后的世界变换 |
| `color` | 判定线基准色（AP 金 / FC 蓝 / 白） |
| `scaleX` / `scaleY` | 扩展事件的缩放（缺省 1） |
| `extColor` / `extColorEnd` | 扩展事件颜色（当前 / 线段末端，用于渐变） |
| `useExtColor` | 该线是否受颜色事件控制 |
| `z` / `theta` | （伪）3D：Z 轴位移（画面高比例，正 = 往屏幕内）与下落面倾角（弧度，正 = 向屏幕内倾） |

谱面级：`state.camera = { x, y, z, angle }`（缺省 `{0, 0, 0, ≈53.13°}`）—— 谱面相机每帧求值的结果，
投影层通过 `opts.camera = state.camera` 取用（`state.camera` 为缺省值时与没有相机逐像素一致）。

音符的每帧状态写在音符对象上：`distY` / `headY` / `tailY` / `visible` / `renderAlpha` / `badStyle`。

## 5. 关键 API

### 5.1 解析与编译

```js
import { detectFormat, prepareChart } from './src/core/model.js';
import { parseOfficialChart } from './src/core/parse-official.js';
import { parseRpeChart } from './src/core/parse-rpe.js';
import { Diagnostics } from './src/core/sanitize.js';

const diagnostics = new Diagnostics();
const chart = prepareChart(parseRpeChart(json, { diagnostics }), { diagnostics });
// chart.diagnostics -> { summary, messages }
// chart.dropped     -> { lines, notes, events }
```

- 解析器与 `prepareChart` **对脏数据不抛异常**，只记录诊断；唯一抛错的情况是「整个输入不是对象」或「传入的不是模型」；
- `detectFormat(json)` 判据：有 `META` 或 `BPMList` → `rpe`；有 `formatVersion` 且有 `judgeLineList` → `official`；其余 `unknown`。

### 5.2 求值与判定

```js
import { createState, evaluate, advanceJudging, advancePlayJudging, resetState, resyncJudgeCursor, resyncPlayCursor } from './src/core/state.js';

const state = createState(chart, { aspect: 16 / 9, autoplay: false });
evaluate(state, timeSeconds);                 // 纯计算：线变换、音符位置 / 可见性
advanceJudging(state, timeSeconds);           // 自动游玩（autoplay: false 时不判定）
advancePlayJudging(state, t, input, { hitTest }); // 真实游玩：input 见 core/input.js，hitTest 为判定范围
```

调用约定：

- `evaluate` 必须在使用状态前调用；`advancePlayJudging` 内部不会调用 `evaluate`；
- 改动音符时间后要重新排序并重置判定游标：`resyncJudgeCursor(state)` / `resyncPlayCursor(state)`；
- `state.hits` 保存本帧新增的打击特效。

### 5.3 投影与拾取

```js
import { createProjection, pickNote, pickLine } from './src/render/projection.js';

const view = createProjection(cssWidth, cssHeight, { aspect: 16 / 9 });
view.toScreenX(worldX); view.toWorldX(screenX);
view.noteTransform(note, lineState, { noteWidthRatio, camera });   // 单次绘制与拾取共用
view.lineCenter(lineState, { camera });                            // 判定线原点（含相机平移与 k）
view.projectLocal(wx, wy, lx, ly, z, { camera });                  // 落点 + 局部偏移 + 深度 → 屏幕
view.judgeBand(note, lineState, { noteWidthRatio, camera });        // 判定带中心与半宽
view.judgeBand(note, lineState, { ignore3D: true });                // 垂直判定：忽略相机与 z / 倾斜
view.lineLocalToScreen(localX, localY0, lineState, opts);           // 判定线局部点 → 屏幕（Hold 逐行投影 / 判定范围轮廓共用）
```

规则：**绘制、拾取、判定范围必须走同一套投影**，否则会出现「看到的和点到的不一致」。
判定范围另有 `toLineChart()`（屏幕点 → 判定线局部坐标的解析逆，倾斜面精确）与 `judgeBandShape()`（判定区域的屏幕多边形，供「显示判定范围」叠加层用）：`hitJudgeBand()` 与 `judgeBandShape()` 是同一套几何，所以叠加层画出来的就是「点哪算命中」，并且跟随当前判定模式（垂直判定 = 等宽列 / 轨道判定 = 楔形 / 全屏判定 = 不画）。
`opts.camera` 传 `state.camera`（谱面相机）；`opts.ignore3D = true` 表示「完全按 2D」（垂直判定）。
（伪）3D 公式与相机语义见 `docs/Phigros文档.md` 的 §3.5 / §3.5.1。

### 5.4 渲染

```js
import { createCanvasRenderer } from './src/render/canvas2d.js';
const renderer = createCanvasRenderer(canvas, textures, options);
renderer.resize(w, h, dpr);
renderer.setBackground(image);
renderer.draw(state, hitEffects);
renderer.pickNote(state, x, y, radius);
renderer.projection;   // 与 view 同构
renderer.stats;        // 上一帧的统计（倾斜 Hold 的 计划行数 / 实际绘制 / 三角形数 / 剔除行数，见 §10 与 tools/measure-tilt-hold.mjs）
```

主要选项：`opts.showLines`、`opts.showNotes`、`opts.multiHint`、`opts.noteWidthRatio`、`opts.backgroundBlur`、`opts.backgroundBrightness`、`opts.showHitFx`、`opts.hitFxScale`、`opts.hitParticles`、`opts.lineTexture`、`opts.showJudgeRange` / `opts.judgeRangeMode`。

倾斜下落面上的 Hold 用**逐行精确四边形**绘制（每行两个裁剪三角形，见 `docs/Phigros文档.md` §3.5）：行数按屏幕长度自适应（18px 一行、上限 24 行）、屏幕外整行剔除；每行还向邻块多要 `HOLD_TILT_SEAM_COVER_PX`（默认 1）个屏幕像素（绘制矩形、源矩形、裁剪一起外扩），用来盖住 `clip` 内缩留下的缝。`renderer.stats` 可以核对这几条规则是否生效。

### 5.5 序列化与导出

```js

import { serializeRpe } from './src/core/serialize-rpe.js';
import { serializeProject, parseProject, createBlankProject } from './src/core/project.js';
import { buildExport, EXPORT_KINDS } from './src/core/export-package.js';
import { loadFilePackage, loadZipPackage, buildPackage } from './src/core/package.js';

const { json, warnings, stats } = serializeRpe(chart);
// buildExport(chart, kind, opts) -> { kind, fileName, blob, entries, warnings, stats, json }
// kind: 'project' | 'rpe' | 'official'；opts.media 传 { song: {name, blob}, background: {...} }
const { fileName, blob, warnings: packWarnings } = await buildExport(chart, 'rpe', { media });
```

- 导出器负责保证目标格式的硬约束（官方的事件列表非空、哨兵、首尾相接、`bpm > 0`）；有损之处写进 `warnings`，由调用方展示；
- **全局流速控制**（`meta.speedMultiplier`，缺省 1）的落地按格式不同：**官谱导出烘焙进数值** —— 判定线速度事件 ×k，官谱口径 Hold（`holdSpeed = 'own'`）自己的 `speed` ×k（它的长度 = `speed × 时长`，不经过判定线）；**RPE 导出不烘焙** —— 只写 `META.speedMultiplier`（本项目的 META 扩展，`parseRpe` 会读回 `meta.speedMultiplier`），事件与音符数值保持原样，RPE 与其它工具按 ×1 显示。普通音符与 RPE 口径 Hold 的 `speed` 在两种导出里都不乘 k（它们已随判定线 ×k，再乘一次会成 k²，与官谱 Hold 的头部固定 1× 不一致）。渲染端在 `state.js` 的 `evaluate` 里应用同一条规则，因此预览、播放器与导出逐值一致（含官谱 Hold 的头部：它由判定线高度积分承担，也正好 ×k）；
- 两个导出器都在根对象的**第一个键**写生成器声明 `generator`（`meta.js` 的 `GENERATOR_STAMP`，含在线地址）；项目文件的 `PROJECT_GENERATOR` 也是同一句（`project.js` 直接引用同一常量）。依据：Phira 的 `PgrChart` / RPE 结构体用 serde 默认行为解析，未知根键会被忽略（本项目的 `camera` 根键也是同样思路）；
- **Hold 速度口径是有损项，但两个方向都按「保持长度」换算**：`holdSpeed = 'line'` 的 Hold 导出官谱时改写成等效尾速度 `η = speed × k × (PJ(endSec) − PJ(tN)) / 时长`（官谱表达不了随时间变化的长度）；`holdSpeed = 'own'` 的 Hold 导出 RPE 时改写成等效流速倍率 `speed′ = speed × 时长 / (PJ(endSec) − PJ(tN))`（`noteToRpe` 的 `speedOverride`），长度与编辑器一致，代价是 RPE 的 `speed` 会同时缩放头尾、头部下落速度随之变化；判定线在该区间没有位移（`PJ(尾) = PJ(头)`）时换不出来，原样写并告警。两种情况都给出告警；
- 导出器读的是**源音符**（`line.notes`，编辑器改的也是它），而 `height` / `tailHeight` 这类派生值只写在编译后的副本上 —— 需要高度时从 `line.rt.heightAt(秒)` 现算，不要去读源对象的派生字段（它们不存在）；
- `parseProject` 的产物与解析器同构，可直接交给 `prepareChart`（`buildPackage` 也用它：包内若有项目文件，`chartJson` 就是它的反序列化结果，因此**播放器能直接载入 `.pce.zip`**）；
- `refreshLine(chart, lineId, { keys, notes, extended })`：局部重编译指定线的派生数据。扩展键可以直接混在 `keys` 里传，函数会自动分流。
- `refreshCamera(chart, keys)`：重编译谱面相机的关键帧（`chart.cameraRt`）。编辑器给相机轨用的哨兵 `lineId = CAMERA_LINE_ID (-1)`：`refreshLine(chart, -1, { keys })` 会转到 `refreshCamera`，于是拖动 / 撤销 / 粘贴这些「按线重编译」的既有路径对相机同样可用。

## 6. 数据流

```
chart.lines[l].layers[k][key]        源事件对象（唯一真值）
chart.lines[l].extended[key]         源扩展事件（不分层；含本项目的 z / theta）
chart.camera[key]                    源相机关键帧（谱面级；键为 x / y / z / angle）
        │
        ├─ tracks.js  makeEventTrack / makeExtendedTrack / makeCameraTrack / makeNotesTrack → clip（派生展示数据）
        │        clip.ev / clip.note 指回源对象；相机 clip 带 `camera: true`
        │
        ├─ 编辑操作：拖动 / 详情面板 / 曲线页 / 添加 / 剪刀 / 粘贴 → 改源对象
        │
        ├─ refreshEventClip(track, index, axis)  就地刷新 clip 派生字段（不重排、不重建）
        │
        └─ refreshLine(chart, lineId, { keys, notes, extended })  局部重编译
        │     事件 → compileLayers → rt[key]
        │     扩展事件 → compileExtended → rt.extended[key]
        │     音符 → timeSec / durationSec / height
        │     lineId = CAMERA_LINE_ID(-1) → refreshCamera(chart, keys) → chart.cameraRt
        ├─ refreshNotes(chart)        音符时间变化后重排、重算结束时间与多押标记
        ├─ resyncJudgeCursor / resyncPlayCursor   判定游标重新定位
        └─ 预览下一帧使用新模型渲染（evaluate 会把相机求值进 state.camera）
```

编辑器侧的完整链路（含撤销栈与播放指针）见 §8。

## 7. 编辑器实现要点

编辑器的目录用途见 §2；以下只记录影响正确性的约定。

| 主题 | 约定 |
| --- | --- |
| 写回 | 拖动 / 详情面板 / 曲线页 / 添加 / 粘贴都直接改源对象，随后 `refreshLine()` 局部重编译；拖动中按 120 ms 节流、松手立刻补一次 |
| 拖动时间 | 起点按「时间轴上的新左边缘」写回（用秒做桥，因为各线 BPM 倍率不同，线内拍 ≠ 时间轴拍）；时长单独保持，不做逐帧累加 |
| 哨兵事件 | `endBeat >= 1e6` 的「保持到结束」事件拖动只挪起点；起点为负数哨兵的事件被拖动后变成具体拍值 |
| 撤销 | 只记改动记录（字段前后值、数组增删位置），不存整谱快照；撤销后按受影响的线重编译派生数据并重建轨道 clip，按**对象身份**恢复选中；栈深 80 |
| 依赖判定的游标 | 任何改变音符时间或顺序的操作后必须调用 `resyncJudgeCursor` / `resyncPlayCursor`，否则会重复判定或漏判 |
| 扩展事件轨道 | 轨道 id 为 `ev:<线号>:ext:<键>`、`layerIndex` 为 `null`；重建派生 clip 时必须走 `makeExtendedTrack`（普通事件轨构造器会读 `layers[null]` 得到空数组，导致轨道上的事件消失） |
| 结构树交互 | **单击 = 导入**（部分浏览器双击不灵），折叠图标负责展开 / 折叠；事件层固定列出 5 类事件、扩展事件组固定列出 5 个已实现键、相机组固定列出 4 个通道，没有事件的那几条显示「空」——单击即可建出空轨，缺的轨道因此也有入口 |
| 快速切线 | 按住 `Tab` 的**全屏**圆环选线菜单（`src/editor/quick-line.js`，挂在 `body` 上、`position: fixed`，避免被面板的 transform / filter 影响）：两圈 × 12 格 = 24 条线。**命中哪一格由鼠标总位移判定**（纯函数 `slotByDrag`：方向 → 12 格，0 在正上方、顺时针；长度 `< DRAG_DEAD (14px)` = 没选、`< DRAG_OUTER (160px)` = 内圈 0–11、`≥` = 外圈 12–23），与指针的绝对位置无关 —— 位移原点 = 按下 `Tab` 时的指针位置（`main.js` 持续记录 `lastPointer`，键盘事件里没有坐标）。`DRAG_OUTER` 取 160px 是刻意的：内圈必须好选（用户反馈 72px 时动不动就跑到外圈）。**主题色是白**（编辑器的 `--accent`）：高亮扇形 / 指引线 / 圆心文字全用白色，「当前线」不再用浅蓝色号而是序号下方一个白点（`.ed-ql-dot`），选中一圈时另一圈淡到 0.28。超过 24 条线用滚轮翻页；载入动作与结构树单击判定线行**共用** `tree.js` 的 `loadLineIntoTimeline()`。覆盖层 `pointer-events: none`，不挡其它操作；展开动画时长与每格错开延迟按「加快 50%」缩放（÷1.5） |
| 全局流速控制 | 谱面总览页的「全局流速控制」行写 `chart.meta.speedMultiplier`（`preview.setMetaField`）。**不需要重编译**：缩放发生在 `state.js` 的 `evaluate`（判定线高度 ×k；官谱口径 Hold 自己的 speed ×k），下一帧预览就是新流速；导出器应用同一条规则（见 §5.5）。缺省 1，非法值退回 1、上限 100（`meta.js` 的 `speedMultiplierOf()`） |
| 新轨道入场动画 | 结构树加轨道后 `timeline.flashNewTracks()` 播放 1.2s 入场：画布上整行白色高亮淡出 + 左侧白色竖条 + 前 40% 时间内一条白线从行中央向两端展开；轨道头同时加 `.ed-track-new`（CSS 关键帧：闪白 + 从左侧推入 10px）。**颜色是白**，不要写回旧的蓝色 `rgba(122,200,255)` |
| 按需建数组 | `clipboard.js` 的 `ensureEventArray(chart, ref)`：事件层 / 扩展事件 / 相机的键缺数组时就地建出来（添加工具与粘贴都走它，于是空轨上能直接放第一条事件、也能直接粘贴） |
| 删掉一条轨 | `timeline.clearTrackData(track)`：把该键的事件逐个记进撤销栈（`history.removed`）后清空数组（保留同一数组对象，撤销时按原下标插回），再 `refreshLine(chart, lineId, { keys })` 重编译；时间轴上那条由结构树 `removeTrack` 移除。**可撤销** |
| 谱面相机轨道 | 相机是**谱面级**的：轨道 id 用 `cam:<通道>`、`camera: true`、`lineId` 用哨兵 `CAMERA_LINE_ID (-1)`、`layerIndex` 为 `null`。重建 clip 走 `makeCameraTrack`；`eventArrayOf` 认 `camera` 标记；拖动写回时相机不按线换算（谱面拍 = 时间轴拍）；`refreshLine(chart, -1, { keys })` 转到 `refreshCamera`。这样拖动 / 撤销 / 粘贴 / 剪刀全部复用既有路径 |
| 颜色事件 | 取值是三元组，详情页按 R/G/B 编辑；曲线页对颜色事件给出提示而不绘制曲线 |
| 预览帧率读数 | `#ed-fps` 的**唯一写入方**是 preview 的渲染循环（每 500ms 用「窗口内帧数 / 窗口时长」算一次，不用逐帧 EMA）。以前 `main.js` 的 `updatePerfHud()` 每秒往同一个元素写「预览 N/s · 时间轴 M/s」，两处互相覆盖 —— 这就是「帧数显示每秒抽搐一下」。现在 `updatePerfHud()` 只算数字（`perf.text`），由 preview 拼成 `NN fps · 时间轴 N/s` 一次写完；CSS 也给读数定宽 + 等宽数字，数字变化不再推动右侧布局 |
| 按住 `T` 试听 | 快捷键：`keydown KeyT` → `preview.play()`；`keyup KeyT` → `preview.stopAndRollback()`（暂停 + 回到本次播放的起点，**与「自动回滚」开关无关**），随后同步时间轴指针。输入框 / 欢迎弹窗里不劫持 |
| Hold 速度口径 | 详情面板的「Hold 速度口径」下拉（仅 Hold）写 `note.src.holdSpeed`（渲染读的是源对象）；取值为 `'line'`（跟随判定线，缺省）/ `'own'`（独立尾速度）。添加工具造出的新 Hold 一律 `'line'`；官方谱导入的 Hold 被解析器标成 `'own'`，**不要静默改成 `'line'`**，否则长度会跟着该线的速度事件变 |
| 未保存状态 | 脏标记由 `timeline.onClipsChanged` / `onModelChanged` 与谱面总览页的改动触发；`beforeunload` 在脏状态下拦截；草稿在改动停止 4 秒后写入，两次写入间隔不小于 15 秒 |
| 草稿存储 | 库 `phichart-editor-drafts`、store `drafts`；记录 `index`（概要）/ `chart`（项目格式 gzip）/ `asset:<名\|大小\|时间>`；单文件 ≤ 8 MB 且合计 ≤ 24 MB 才随草稿保存；无 IndexedDB 时退化为内存后端 |
| 界面文案 | 简短、正式，不使用口语与日志式输出；同一信息只出现一处（详见 §10） |

### 7.1 纠错规则

规则表在 `src/editor/lint.js` 的 `RULES`，共 18 项。级别只有两条标准：**错误** = 理论上会影响渲染或导出；**警告** = 多半是笔误但能正常渲染。

| 规则 | 级别 | 判定 | 后果 |
| --- | --- | --- | --- |
| 音符字段非法 | 错误 | 时间 / `positionX` 不是有限数值 | 进不了 `line.rt.notes`；导出写出 `NaN` |
| 未知音符类型 | 错误 | 不是 tap / drag / hold / flick | 不显示也不判定；导出写出非法编号 |
| Hold 负时长 | 错误 | `endBeat < startBeat` | 渲染把结尾夹回头部；导出非法 |
| X/Y 位移不成对 | 错误 | 同层 X 位移与 Y 位移条数不同，或条数相同但第 i 条起止拍对不上 | RPE 按索引配对，多余的被丢掉、后面的错位；官方格式无法表达 |
| 「保持到结束」不在末位 | 错误 | 哨兵 `endBeat` 之后还有事件 | 后面的事件永远不生效 |
| 事件负时长 | 错误 | `endBeat < startBeat` | `compileEventList` 整条跳过 |
| 事件字段非法 | 错误 | 时间 / 取值不是有限数值 | 该事件被跳过，该时段取上一条的值 |
| 音符重叠 | 警告 | 同一线 `positionX` 与所在面相同且时间区间相交（涉及 Hold 的不报） | 玩法上要同一时刻同一位置打两下 |
| 事件重叠 | 警告 | 同一线同一类型跨层合并后区间相交 | 按「后开始的生效」，前一条尾段被吃掉 |
| `positionX` 超界 | 警告 | `\|positionX\| > 8.889`（画面半宽） | 音符落在画面外 |
| Hold 时长为 0 | 警告 | Hold `endBeat == startBeat` | 退化为单点判定 |
| 非 Hold 带时长 | 警告 | Tap / Drag / Flick 的 `endBeat > startBeat` | 时长被忽略（多半是选错了类型） |
| 音符速度非法 | 警告 | 音符自身 `speed ≤ 0` | `0` 会一直贴线，负值反向下落 |
| 音符时间为负 | 警告 | `startBeat < 0` | 谱面一开始就已落线 |
| 事件值越界 | 警告 | 不透明度不在 −1~1、x/y 绝对值超过 10、旋转超过 1000 rad、速度绝对值超过 10000、扩展缩放 ≤ 0 或 > 100、`z` 绝对值 > 2、`theta` 绝对值 > 90° | 多数是单位写错（把 RPE 的 675 填进比例单位） |
| 相机取值越界 | 警告 | 相机 `x` / `y` / `z` 绝对值 > 10（画面比例） | 多半把长度单位当比例填了（界面按长度单位填） |
| 相机视角非法 | 错误 | 相机 `angle` 不在 0°–180° 之间 | 渲染退回默认视角，相机动画等于没写 |
| 事件未按时间排序 | 警告 | 数组没有按 `startBeat` 升序 | 本项目会重排，但直接读原始 JSON 的工具会按原顺序处理 |

四条刻意的语义（避免在真实谱面上刷假警告）：零长事件合法（RPE 的瞬时事件就是 `startBeat == endBeat`）；正 / 背面分开算重叠；速度 0 与负值不算错误；只做单向位移不报。阈值按内部规范单位取值，并用真实谱面校准到 0 命中（实测极值：`|positionX| ≤ 7.49`、`x ∈ [−1.3, 1.3]`、`y ∈ [−2.5, 4.5]`、`|rotate| ≤ 37`、`alpha ∈ [0, 1]`、`speed ∈ [−1.1, 999]`，故 x/y 取 10、rotate 取 1000、speed 取 10000）。

调度策略：载入谱面后自动分片扫描；数据变动后防抖 900 ms 重扫（不在前台也扫，只跳过列表重绘）；按判定线签名缓存结果，签名包含扩展事件取值，**谱面相机单独占一条（哨兵 `lineId = -1`）**，改动相机只重扫这一条。

## 8. 编辑器数据流

```
用户操作（拖动 / 面板 / 添加 / 剪刀 / 粘贴）
        │
        ├─ history.begin(label) + 记录改动前的字段值 / 数组位置
        ├─ 改源对象（事件 startBeat/endBeat/start/end，音符 startBeat/endBeat/positionX + note.src）
        ├─ refreshEventClip / refreshLine / refreshNotes（按需）
        ├─ rebuildTrackAfterInsert / rebuildTrackAfterSplit / rebuildTracksFor
        ├─ history.commit()
        └─ onClipsChanged / onModelChanged
                ├─ 详情面板与曲线页刷新
                ├─ 纠错页标脏（防抖 900 ms 后重扫）
                └─ 自动保存脏标记 + 角标 + 草稿去抖写入
```

时间轴与结构树都从 `chart` 读取，因此任何一处改动都会在下一帧的预览与重绘中体现。撤销 / 重做走同一条收尾路径，保证预览、时间轴、纠错三者一致。

## 9. 播放器：暂停页与游玩模式

播放器的界面状态只有三个整屏界面（`src/app/main.js` 的 `showScreen`）：`pause`（暂停页）、`play`（播放中，只显示 HUD 与左上角暂停键）、`result`（结算）。

暂停页是**黑色半透明全屏遮罩 + 一层面板**，面板内部再分三层（`showPausePage`）：

| 继续 | `play.svg` | 38（基准 ×0.8） |

约定与易错点：

- **暂停页不显示任何文字**：主层不写文案，信息只通过 `title` 提示表达；谱面信息只在设置页。改版时不要在主页添加标题。
- 图标按钮一律用 `setIcon(btn, name, { size })` 注入，**必须给 `size`**：不给则 span 没有宽高，图标不可见（真浏览器自检会拦住这个错误）。`styles.css` 里只定义按钮的点击区，**不要给 `.pause-icon .ic` 写死尺寸**，否则会覆盖行内尺寸。
- 图标可见性依赖 `styles.css` 里的 `.ic` 基础样式（`background-color: currentColor` + `mask: var(--ic-url)`）；播放器页原本没有这条规则，整排图标会「什么都不显示」。
- 「自动游玩」按钮与设置页的「触屏游玩」复选框是**同一份状态**（`setPlayMode`，反面关系）：切换后停在暂停页，不进入播放；非触屏设备与未载入谱面时按钮置灰。
- 没有谱面时启动直接停在 `open` 层；载入成功后 `setChart` 回到 `main` 层并把倍速复位（**判定范围保留玩家自己的选择**，它记忆在 `localStorage` 的 `phichart.judgeArea` 里）。
- 判定范围三档：`band`（垂直判定，`ignore3D: true`）/ `tilt`（轨道判定，跟着相机与 `z` / 倾斜）/ `screen`（全屏判定，不传 `hitTest`）。
- 载入提示（`pauseStatus`）写在 `open` 层自己的状态行里，不占用 HUD；HUD 的状态行只在播放中可见。
- 触屏游玩的事件接线在 `src/app/touch-input.js`，绑在**画布**上；暂停页浮层是画布的兄弟节点，界面控件因此天然不参与判定（`isUiTarget` 另外兜底过滤 `.screen` / `button` / `input` 等目标）。
- **曲终结算等音频播完**：`checkRunEnd()` 除了「全部音符判完」还要求 `audioSettled()`（音频位置到达 `duration`；没有音频时视作已播完）。所以谱面比音频短时会继续放尾奏，等音乐自然结束再跳结算；音乐先结束（谱面更长）则由 `player.onEnded` 直接收尾，不会卡在游玩页。

## 11. 开发约定

### 11.1 文案风格

界面文案、提示与文档统一遵循：

1. **简短、正式**：不使用口语、感叹与冗余修饰；单条提示不超过一句话；
2. **避免日志式输出**：界面不显示过程记录，只说明结果或当前状态；
3. **能删就删**：同一信息只出现在一处，重复说明与显而易见的操作提示一律删除；
4. **信息优先**：需要用户决策时才提示；
5. **术语统一**：判定线、音符、事件层、事件块、谱面包、项目文件、速度（Y/s）。

代码注释与提交信息同样遵循以上要求。

### 11.2 代码约定

| 项 | 约定 |
| --- | --- |
| 模块格式 | 原生 ES 模块，显式 `.js` 后缀；不使用打包器与转译 |
| 依赖 | 运行时零第三方依赖；新增依赖前先确认能否用平台 API 实现 |
| 单位 | 只在 `parse-*.js` / `serialize-*.js` 做格式换算；内核统一用 §4.1 的规范单位 |
| 脏数据 | 解析与编译层不抛异常，改用 `Diagnostics` 记录；求值层做有限性兜底 |
| DOM | `src/core` 不依赖 DOM；测试通过桩件提供 `document` / `Image` / `fetch` |
| 注释 | 写「为什么」而不是「做了什么」；结论性数字必须能追溯到 [Phigros文档.md](Phigros文档.md) 的依据标记 |
| 新增格式特性 | 同步更新 [Phigros文档.md](Phigros文档.md) 的实现状态表与 `docs` 内的交叉引用 |

### 11.3 文档体系

## 12. 已知缺口与后续方向

| 方向 | 现状与计划 |
| --- | --- |
| 增量重编译 | `prepareChart` 仍是全量（1417 音符 + 8.1 万事件约 0.2–0.5 s）；编辑器已用 `refreshLine()` 按线重编译，可进一步拆成 `compileLine()` |
| 大谱面加载 | 40 MB JSON 在主线程 `JSON.parse`（约 0.3–1 s，界面短暂卡住）；计划移到 Web Worker 或按需解析 |
| 求值规模 | `evaluate` 每帧遍历全部音符（带可见性早退）；可改为按时间窗口 + 每线游标索引 |
| 后处理与叠加层 | 现为单 canvas；计划抽象「绘制指令列表」，加 WebGL2 后端与独立叠加层 |
| 真实游玩的输入 | 触屏已实现；缺外接键盘 / 手柄、成绩保存与排名、评级（φ / V / S / A…） |
| RPE 未实现字段 | 扩展事件 `incline` / `text` / `paint` / `gif`、各 `*Control`、`attachUI`、`isGif`、逐音符 `hitsound`、`anchor`、`line.csv` |
| 直接写回原文件 | 计划接入 File System Access（`showSaveFilePicker` / `showDirectoryPicker`），把句柄存入 IndexedDB 以便重开页面恢复 |
| 音频与校准 | 无波形与节拍预览、无音频延迟校准面板 |
| 编辑器体验 | 无拖动排序事件层、无跨谱面粘贴、放置后不能立即指定缓动、无触屏编辑与 PWA 离线版 |

仍未解决的格式层疑问集中在 [Phigros文档.md §9](Phigros文档.md)。
