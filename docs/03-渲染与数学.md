## 1. 坐标系与变换链

### 1.1 两套坐标空间

| 空间 | 原点 | 单位 | 备注 |
| --- | --- | --- | --- |
| 官方 `formatVersion 3` | 屏幕左下角 | x、y ∈ [0,1]（右上角 (1,1)） | 移动事件的 `start/start2` |
| 官方 `formatVersion 1` | 屏幕左下角 | 右上角 (880,520)，事件值 = `1000x + y` | 见 `docs/01` §2.1 |
| RPE | **屏幕中心** | x ∈ [−675,675]（= 屏宽），y ∈ [−450,450]（= 屏高） | 即 1 单位 = W/1350、H/900 |
| 官方内部量 | — | `X = 0.05625 W`（note 横向）、`Y = 0.6 H`（note 纵向/速度） | 建议作为本项目内部统一单位 |

**建议**：内部统一为一个「以屏幕中心为原点、x ∈ [−1,1] 对应屏宽、y 以 0.6H 为单位」的坐标空间（prpr 的做法），解析层负责把三种来源换算进来。

### 1.2 单个音符的屏幕位置

```
lineA = 判定线在 t 时刻的旋转角（弧度，逆时针为正）+ 父线旋转（若继承）
lineP = 判定线在 t 时刻的中心位置（屏幕坐标）+ 父线平移

# 沿判定线方向（局部 +x）
dx_local = Note.positionX × 0.05625 × W           # 官方；RPE: positionX × (W/1350)
# 垂直于判定线方向（局部 +y，正面为正）
dy_local = Y(t) × 0.6 × H                          # Y(t) 见 §2；RPE 直接用它自己的 y 单位

notePos = lineP + R(lineA) · (dx_local, ±dy_local)
```

- `notesBelow`（官方）或 `above != 1`（RPE）的音符从线的背面下落，即 `dy_local` 取反（一般实现为「下方音符在线的另一侧」）。
- 音符贴图本身与判定线平行：渲染时旋转 `lineA`（Flick 等贴图自带的方向由贴图决定）。

### 1.3 判定线的渲染参数

| 参数 | 值 | 来源 |
| --- | --- | --- |
| 长度 | **5.76 H**（6220.8 px @1920×1080；与屏幕高度成正比，与宽度无关） | `[文档]` Lchzh 实测（v1.6.11 / v2.3.1 两处一致） |
| 宽度 | 名义 0.0075 H（8.1 px） | `[文档]`，实测 (6.712±0.997)×10⁻³ H；Phira 绘制时用 0.01（缩放状态下 0.0076）画布单位，≈0.006 H |
| 颜色（普通） | 白 `#ffffff` | `[文档]` |
| 颜色（FC / 全连） | `#a2eeff`（浅蓝） | `[文档]` Lchzh 实测；Phira 资源包默认 `colorGood = 0xebb4e1ff` |
| 颜色（AP / 全 Perfect） | `#feffa9`（金） | `[文档]` Lchzh 实测；Phira 资源包默认 `colorPerfect = 0xe1ffec9f` |
| 不透明度叠加（多条线重叠时） | `a = a1 + a2 − a1a2` | `[文档]` |
| 线的 alpha 也作用于其上的音符 | 音符总 alpha = 线 alpha × 音符 alpha | `[文档]`（RPE：负 alpha 事件会连音符一起隐藏） |

> `[未验证]` 项目原始说明写「长度为 3.6 × 屏幕宽度、颜色 (255,243,163)」与上述实测不符（3.6 W @16:9 = 6.4 H ≠ 5.76 H；`#FFF3A3` ≠ `#FEFFA9`）。实现时以实测值为准，并把长度做成可配置项。

### 1.4 绘制顺序与层级

- 官方格式没有层级字段：按 `judgeLineList` 顺序绘制即可（官谱以此控制遮挡）。
- RPE 有 `zOrder`（约 ±100）决定线的图层；`isCover = 1` 时「线背面的音符」不渲染（即线会遮住背面音符）。
- 音符与线的关系：同一根线上的音符跟随该线一起变换（旋转/平移），因此「躲在另一根线后面」是通过多条线的绘制顺序与 `isCover` 实现的。

### 1.5 父线（RPE）

- `father` = 父线索引（−1 表示无父线），父线可嵌套。
- 子线的位置需要叠加父线变换；是否继承父线**旋转**取决于 `rotateWithFather`（缺省视为 `false`，兼容 163 以前版本）。
- 实现建议：解析时展平成「世界变换」缓存，避免每帧递归；但父线动画变化时需要重算。

## 2. 核心公式：速度积分与音符位置

### 2.1 判定线的实时速度与垂直位置（官方）

设速度事件列表第 k 条为 `{startTime: tk, endTime: tk+1, value: vk}`，判定线在事件开始时刻的累计垂直位置为 `pk`（单位 Y）：

```
p1 = 0
pk = p(k-1) + v(k-1) × (tk − t(k-1)) × 1.875 / bpm          # k ≥ 2

VJ(t) = vk                                                  # Y/s
PJ(t) = pk + vk × (t − tk) × 1.875 / bpm                    # Y，tk ≤ t < tk+1
```

`[文档]`（Lchzh《相关计算》）。注意 `(tk − t(k-1)) × 1.875 / bpm` 就是把时间单位 `T` 换算成秒；**积分变量是秒**，不是拍。

规范化补充 `[文档]`：若第一条速度事件的 `startTime ≠ 0`，等价于在它前面插入一条 `[0, startTime] value = 1` 的事件（RPE/官谱实现均如此）。Phira 的实现更直接：把首条事件的 `startTime` 强制置 0。

### 2.2 音符位置（官方）

```
pN = Note.floorPosition            # 应当等于 PJ(Note.time)，游戏会重新计算
η  = Note.speed                    # 非 Hold；Hold 头部速度为 1，η 用于尾部

非 Hold：            Y(t) = η × (pN − PJ(t))
Hold 头部 (t ≤ tN)： Y(t) = pN − PJ(t)
Hold 尾部：          YT(t) = Y(t) + η × tH × 1.875 / bpm          # tH = holdTime
Hold 已命中后尾部：  YT(t) = η × (tN + tH − t) × 1.875 / bpm      # 尾部从线上继续"收"回
```

`[文档]`。`[实测]` 官方样本第 1 条判定线 280 个 note 的 `floorPosition` 与 `PJ(time)` 逐一相等（含 `speed = 999` 的 note），因此**实现时推荐直接用速度事件积分求 `PJ`，不要去读 `Note.floorPosition`**（旧版速度事件里的同名字段也已被游戏忽略）。

### 2.3 RPE 侧

RPE 没有存储 `floorPosition`，需要在导入时**自行生成**：

```
1) 用 §1 把 Beat 时间轴转成秒；
2) 速度事件按 §4.1(格式说明) 的系数换算成 Y/s；
3) 对换算后的速度做「对秒积分」→ 得到该线的 PJ(t) 关键帧；
4) 每个 note 的 pN = PJ(note.startTime)，Hold 的尾高度 = PJ(note.endTime)。
```

位置换算：`note.positionX / 675 → prpr 画布 x`（`[文档]` Phira），即 `positionX × (W/1350)`。

**yOffset**：`实际偏移（RPE y 单位）= yOffset × speed`；`speed = 0` 时偏移为 0。

## 3. 可见性剔除（性能与正确性都相关）

官方实测规则 `[文档]`（v2.3.1 / v2.0.0）：

| 条件 | 结果 |
| --- | --- |
| `currentFloorPosition < −0.001` 且未打击 | 不渲染（浮点误差规则微妙，原文给出了逐位实现） |
| `speed × currentFloorPosition > 3.3333336`（即 Y > 2H） | 不渲染（v2.0.0+；3.3333336 与 3.3333337 的分界来自 float32 与 0.6 的乘积） |
| Hold 长度为 0（`speed = 0` 或 `holdTime` 取整后为 0） | 不渲染 |
| RPE `visibleTime` | 仅当 `t ≥ note.time − visibleTime` 秒时才可见（默认 999999 = 一直可见） |
| RPE `isCover = 1` | 线背面的音符不渲染（已打击的音符也不渲染） |
| `isFake`（RPE） | 照常下落渲染，但不判定、无特效音效、不计分、不计物量 |

实现建议：不要照抄浮点边界，统一用「`0 ≤ 距离 ≤ 2H` 才渲染」的保守判据，再加一个可选的 float32 精确模式。

## 4. 判定、计分与自动游玩

### 4.1 判定窗口 `[文档]`

| 判定 | Tap / Hold | Drag | Flick | 判定分比例 |
| --- | --- | --- | --- | --- |
| Perfect | ±80 ms | ±100 ms | ±140 ms | 100% |
| Good | ±80–180 ms | — | — | 65% |
| Bad | ±180–220 ms（Hold 无 Bad） | — | — | 0% |
| Miss | 未命中 | 未命中 | 未命中 | 0% |

其它规则：一次点击只能判定一个 Tap/Hold（优先最早出现的可判定音符）；Drag 只需判定时刻有手指在判定区域；Flick 需滑动；Hold 可提前松手/换手，已判 Miss 的 Hold 不能再次判定。

### 4.2 计分 `[文档]`

```
物量 N            = 谱面全部 note 数（含 Hold；假音符是否计入需按格式定义处理）
判定分 = 900000 × (Σ 各 note 判定比例) / N          # Perfect 1.0、Good 0.65、其余 0
连击分 = 100000 × maxCombo / N                      # 就近取整
总分   = 判定分 + 连击分        （上限 1000000）
准确率 = 判定分 / 900000
```

显示相关 `[文档]`（v2.3.1 实测）：实时分数 ≥ 1000000 时恒显示 `1000000`；否则显示为 `'0' + (round(score) / 1e5).toFixed(5)` 去掉小数点（例如 7812.5 → `0007813`）。

> `[实测]` 侧证：RPE 的 `numOfNotes` 定义是「含 FakeNote、**不含 Hold**」，与游戏的物量计算并不等同——说明各工具对「物量」的定义不一致。本项目应自行按「所有参与判定的音符」计算，并把假音符排除。

### 4.3 本项目的自动游玩（预览）策略

按项目要求：**note 落到线上即视为被击中** → 直接记 Perfect、累加连击、在落点播放 42 帧打击动画与打击音效（`click.wav` / `drag.wav` / `flick.wav`）。Hold 的头部命中后循环播放打击动画，尾部到达时结束。

## 5. 时间与音频同步

- 谱面时间与音乐时间的关系 `[文档]`：`谱面时间 = 音乐时间 − offset`；Phira 的表述为「offset 为正时，若音乐同时开始，谱面开始更晚」。
- RPE 的 `offset` 单位是毫秒，官方是秒——导入时必须换算。
- 官方播放流程要点 `[文档]`：音乐进度到 `音乐时长 − 0.22049 s` 时停止播放并结算；进度条长度按音乐时长。
- 编辑器需要的能力（项目要求）：精准跳转（seek）、暂停/继续、倍速播放。
  - Web 端：`AudioContext.currentTime` + `AudioBufferSourceNode.start(when, offset)` 是最可靠的方案（避免 `<audio>` 元素的 seek 精度与抖动）；倍速用 `playbackRate`，但注意它与 `start(offset)` 的组合语义；音频解码优先 `decodeAudioData`（整曲解码到内存，便于随机 seek）。
  - 参考实现 `[文档]`：prpr 使用 `sasa` 音频库，Phira 文档提到「mp3 可能产生不可预测的延迟，建议使用 ogg」。
- 建议的时钟设计：以音频时钟为主时钟，渲染帧用 `chartTime = audioTime − offset` 求值；编辑器里另加一个「无音频时钟」（滚动预览）作为可选模式。

## 6. 性能设计要点

来源：官方实测 `[文档]` + 项目需求。

1. **官方引擎读 note 是 O(n²)**（65536 note 需 6 s），我们绝不能继承：解析时一次性构建好数据，渲染时用「按时间排序 + 游标推进」或「分块索引」。
2. **事件求值**：把每条事件列表编译成关键帧数组（时间为秒），运行时二分查找 + 线性/缓动插值；一帧只求值一次（每条线每种属性一次），不要把事件遍历写进 note 循环。
3. **同屏数千事件（编辑器）**：事件列表/时间轴用「分桶 + 视口裁剪」，只绘制可见时间窗内的事件；波形/事件块用纹理实例化或批量 `drawQuad`，避免逐个创建对象。
4. **贴图批处理**：note 贴图共 8 张（4 类型 × 普通/HL）+ hit 图集；同屏半透明绘制应保持同一图集、减少状态切换（`assets/` 里所有图都是 RGBA8，可直接打图集）。
5. **打击特效**：`hit.png` 是 7×6 = 42 帧的图集，按「帧索引 = 进度 × 42」取子矩形，避免 42 张贴图。
6. **数值精度**：官方是 float32。若要与游戏表现逐一对照（例如研究「3.3333336 才可见」这类边界），内部可用 f32 计算关键量；否则用 f64 更稳。
7. **3D 预留**：把「屏幕坐标」与「渲染变换」分层——上层只产出 (位置, 旋转, 缩放, alpha, 颜色, 纹理) 的绘制指令列表，渲染后端（2D / 伪 3D / WebGPU）各自消费，即可无痛替换。

## 7. 求值伪代码（建议实现形态）

```ts
// 线：速度事件 -> PJ 关键帧（单位 Y，时间单位秒）
function buildFloorPosition(speedEvents, bpm) {
  const kf = [];
  let pos = 0;
  const r = 1.875 / bpm;                       // T -> 秒
  for (const e of speedEvents) {               // 事件必须已按 startTime 排序
    kf.push({ t: e.startTime * r, v: pos, v0: e.value });  // 段起点：位置 pos，速度 e.value
    pos += (e.endTime - e.startTime) * r * e.value;
  }
  kf.push({ t: Infinity, v: pos, v0: 0 });     // 末段（哨兵事件之后）
  return kf;
}

// 任意时刻求值：二分找到所在段
function floorPositionAt(kf, t) {
  const i = upperBound(kf, t) - 1;
  return kf[i].v + (t - kf[i].t) * kf[i].v0;
}

// note 距线的垂直距离（单位 Y）
function noteDistance(note, kf, t) {
  const pN = floorPositionAt(kf, note.time);   // == note.floorPosition（官方）
  if (note.type === HOLD) {
    const head = Math.max(pN - floorPositionAt(kf, t), 0);
    ...
  }
  return note.speed * (pN - floorPositionAt(kf, t));
}
```

## 8. 参考实现的关键常数与规则

来源：**lchzh3473/sim-phi**（官方格式模拟器，`src/core.ts` / `src/index.ts`）`[文档]`；与 prpr 的实现互相印证 `[文档]`。这套数值可以直接作为渲染器的起点。

| 项 | 值 | 出处 |
| --- | --- | --- |
| 画面画布 | `画布宽 = min(实际宽, 实际高 × 16/9)`，高 = 实际高（超宽屏加黑边） | sim-phi `_resizeCanvas` |
| 判定线贴图 | 6220.8 × 7.68 px（1920×1080 参考），绘制缩放 = 画布高 / 1080（宽高比 > 4:3 时） | sim-phi `drawLine`、`line.imageW/H` |
| 判定线缩放基准 | `lineScale = H / 18.75`（宽高比 > 4:3；否则 `W / 14.0625`），UI 文字与线共用该基准 | sim-phi |
| X 单位（像素） | `0.05625 × 画布宽` | sim-phi `transformView` |
| Y 单位（像素） | `0.6 × 画布高` | sim-phi `transformView`（注释：控制 note 流速） |
| 音符贴图归一化 | `noteScaleRatio = 画布宽 × noteScale / 8080`；各贴图先按 `8080 / 原图宽度` 预缩放（本项目 `Tap.png` 原宽 989 px） | sim-phi `noteScaleRatio` / `noteRender.update` |
| 打击特效缩放 | `noteScaleRatio × 6` | sim-phi `hitImageList` |
| 打击特效配色 | Perfect `rgba(255,236,160,0.882)`；Good `rgba(180,225,255,0.922)` | sim-phi `imgShader` |
| Bad 状态的音符 | 用 Tap 贴图整体着色 `#6C4343`，并在 500 ms 内淡出 | sim-phi `drawTap` |
| 音符过线淡出 | **0.16 s**（`alpha = max(1 − (t − t_hit)/0.16, 0)`） | sim-phi；prpr `FADEOUT_TIME = 0.16` 一致 |
| 判定区域宽度 | `0.118125 × 画布宽`（= 2.1 X） | sim-phi `judgeWidth` |
| HL（高亮/多押）贴图 | 当同一时刻存在 ≥ 2 个音符（按秒四舍五入到 1e-6 比较）且开启「多押提示」时，使用 `*HL` 贴图 | sim-phi `isMulti` / `drawTap` |
| Hold 打击特效间隔 | 与 bpm 成反比（`(now − lastHit) × holdTime ≥ 1.6e4 × holdSeconds`） | sim-phi `execute` |
| 音符可见性 | `maxVisiblePos < line.positionY2` 判隐藏（float32 位操作，见官方实测数据）；另有 `Y(t) × 0.6 > 2`（> 2 屏幕高）判隐藏 | sim-phi `getMaxVisiblePos` / `setAlpha` |
| 渲染顺序 | 判定线（背景后 → 背景前）→ Hold → Drag → Tap → Flick → 打击特效 → UI | sim-phi `drawFrame` |
| floorPosition 计算 | 全程使用 `Math.fround`（float32）逐项累加，且 `dy = (endTime − startTime)/bpm × 1.875`（秒） | sim-phi `prerenderChart` |

**实现建议**：先用 §7 的伪代码 + 本表常数做出「看起来正确」的渲染，再按 §3 的剔除规则和 float32 细节逐步逼近游戏表现。
