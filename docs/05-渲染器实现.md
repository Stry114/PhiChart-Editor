# 05 · 渲染器 v1 实现说明

> 本文说明 v1 渲染器的**兼容方案（内部统一模型）**、目录结构、运行方式、已实现/未实现范围与测试结果。
> 结论依据：`docs/01`~`docs/04` 的格式规格，以及 `tools/render-tests.mjs`、`tools/render-smoke.mjs`、`tools/http-smoke.mjs` 的实测。
> 范围：按需求**只渲染关卡本体**，不含开场/结束动画、不含编辑器 UI。

---

## 1. 运行方式

需要一个静态服务器（浏览器模块 + `fetch` 同源限制），在项目根目录执行任一条：

```powershell
# Windows 一键：找 Python、起服务器、开浏览器
.\启动渲染器.cmd

# 或手动
python -m http.server 8099
npx --yes serve -l 8099 .
```

然后打开 <http://127.0.0.1:8099/index.html>。

### 1.1 打开仓库里的两个测试包

- **内置示例包按钮**（页面左侧「载入谱面」下，需 http 环境）：直接读取 `packages/` 下的谱面 + 音频 + 曲绘。
  - `白复生 AT（official）` → `packages/白复生 AT（official格式）/Chart_AT #3649.json`（24 线 / 1156 音符）
  - `领土战争 AT（RPE）` → `packages/领土战争AT（RPE格式）/29519800.json`（24 线 / 1417 音符 / 8.1 万事件）
- **选择谱面包目录**：选上面任一目录（`webkitdirectory`），会自己找谱面 JSON、音乐（体积最大的音频）、曲绘，并解析 `info.txt` / `info.csv`。
- **拖拽**：把包文件夹或 zip 拖进窗口。
- **选择 zip**：`loadZipPackage` 用浏览器自带的 `DecompressionStream('deflate-raw')` 解压，无第三方依赖。
- **只选谱面 JSON**：没有音乐/曲绘时也能预览（用于检查结构）。

> `file://` 直接打开 `index.html` 时，`fetch` 取不到内置示例包，请用「目录 / zip / 拖拽」方式载入。
> 文件名里的空格与 `#`（如 `Chart_AT #3649.json`）在代码里统一按路径分段 `encodeURIComponent` 处理。

- 快捷键：`空格` 播放/暂停、`←/→` ±5s、`R` 重开、`[` `]` 倍速、`N` `M` 调整音符宽度（默认 W/8，步长 0.5% 画面宽）。

## 3. 兼容两种格式的方案：内部统一模型

思路：**以 RPE 的概念为超集，官方格式向它对齐**。官方缺少的东西（变速、事件层、缓动、假音符……）在模型里天然是「默认值/单层/线性」；RPE 缺少的东西（官方 v3 的归一化坐标）在解析时折算成同一坐标。

| 量 | 官方格式 | RPE 格式 | 内部统一表示 |
| --- | --- | --- | --- |
| 时间 | `time`（1/32 拍）→ `time / 32` 拍 | `Beat = [a,b,c]` → `a + b/c` 拍 | 模型层：**拍**；运行期：**秒**（由 `timeline` 换算） |
| 速度变化 | 每条线一个 `bpm`（恒定） | 全局 `BPMList` + 每条线 `bpmFactor` | `timeline = createTimeline(bpmList, bpmFactor)`，`秒 = 拍 × 60 / (bpm / bpmFactor)` |
| 判定线位置 | v3：`x=start/end`、`y=start2/end2`（0..1，左下角原点）→ `值 − 0.5`；v1：`1000x+y` → `x/880 − 0.5`、`y/520 − 0.5` | `x/1350`、`y/900`（屏幕中心为原点） | **以画面中心为原点的比例偏移**（x 相对画面宽、y 相对画面高，y 向上为正） |
| 旋转 | 度，逆时针为正 → 弧度 | 度，顺时针为正 → **取负**后转弧度 | 弧度，逆时针为正 |
| 不透明度 | `judgeLineDisappearEvents`，0..1 | `alphaEvents`，0..255 → `/255` | 0..1 |
| 下落速度 | `speedEvents.value`（Y/s） | 速度值 × **2/9** | Y/s（1 Y = 0.6 画面高） |
| 音符横向位置 | `positionX`（X 单位） | `positionX × 1/75.9375` | X 单位（1 X = 0.05625 画面宽） |
| 音符类型 | 1 Tap / 2 Drag / 3 Hold / 4 Flick | 1 Tap / 2 Hold / 3 Flick / 4 Drag | `'tap' \| 'drag' \| 'hold' \| 'flick'` |
| 上下方向 | `notesAbove` / `notesBelow` 两个数组 | 每个音符 `above`（1 = 正面） | `note.above: boolean` |
| Hold 长度 | `holdTime`（1/32 拍） | `startTime` → `endTime` | `durationSec`（编译时算好） |
| 其它音符属性 | 无 | `alpha`/`size`/`speed`/`yOffset`/`visibleTime`/`isFake`/`hitsound`/`tint`/`judgeArea` | 同名规范字段（`alpha` 0..1、`yOffset` 换算成 Y、`visibleTime` 秒或 `Infinity`） |
| 偏移 | `offset`（秒） | `META.offset`（毫秒 → `/1000`） | 秒；`谱面时间 = 音乐时间 − offset` |
| 事件层 | 只有一层 | 最多 5 层 | `line.layers[]`，每层含 `x/y/rotate/alpha/speed` 五类事件 |

### 3.1 事件层与默认值

- 求值规则：**只有「含该事件的层」参与求和**；所有层都没有该事件时取默认值：`x = y = rotate = 0`（画面中心/不旋转）、`alpha = 0`（不显示）、`speed = 1 Y/s`。
- 这与 RPE 的语义一致（层相加、新建判定线自带覆盖全时间的 alpha 事件），也与官方「每条线都有 4 类事件数组」的写法兼容。
- 事件求值：把每层每类事件编译成「按秒排序的关键帧」，运行期二分查找 + 缓动插值，**O(log n)**。
- 判定线高度 `PJ(t)`：速度事件对**秒**积分（`docs/03 §2`）；官方若首条速度事件 `startTime ≠ 0`，自动补一条 `[0, startTime] value = 1` 的隐含事件。

### 3.2 与官方/参考实现的一致性验证

- `tools/render-tests.mjs` 用官方样本第 1 条判定线的 **280 个音符**逐一比对：内部算出的 `height` 与谱面里存的 `floorPosition` 一致（最大误差 4.07e-4，属于官方 float32 存储的舍入）。
- RPE 速度换算用样本中的「瞬移」值交叉验证：`4495.5 × 2/9 = 999`，与官方样本的 `999` 一致。

## 4. 渲染管线（每帧）

1. `player.chartTime()` 取得谱面时间（音频时钟 − offset；无音频时用 `AudioContext.currentTime`/`performance.now` 时钟）。
2. `evaluate(state, t)`：算每条判定线的 `worldX/worldY/worldRotate/alpha/PJ(t)`（含父子线叠加），以及每个音符的 `distY`、Hold 的头尾、可见性与透明度。
3. `advanceJudging(state, t)`：自动游玩判定（音符落到线上即 Perfect）、累计连击/分数、产出打击特效。
4. `renderer.draw(state, hits)`：背景 → 判定线 → 音符（Hold → Drag → Tap → Flick）→ 打击特效。

### 4.1 像素换算

```
画面区域 = 16:9 contain 适配（areaW = min(画布宽, 画布高 × 16/9)，height = 画布高）
screenX = cx + worldX(画面宽比例) × areaW
screenY = cy − worldY(画面高比例) × areaH
音符局部：dx = positionX × 0.05625 × areaW
          dy = Y(t) × 0.6 × areaH
背面音符：额外旋转 180° 且 dx 取反（与 lchzh 模拟器一致）
```

### 4.2 视觉常量（当前取值与依据）

| 项 | 取值 | 依据 |
| --- | --- | --- |

### 4.3 判定与计分

- v1 只有**自动游玩**：`t ≥ note.timeSec` 即判 Perfect（Hold 只判头部），连击 +1。
- 计分与官方/Phira/sim-phi 一致：`score = round((900000·Perfect + 585000·Good + 100000·maxCombo) / N)`，`N` = 非假音符数（Drag 计入）；分数显示用与游戏一致的 `0 + 定点` 格式。
- 测试断言：两套样本跑完整时间轴后 `score = 1000000`、`maxCombo = 物量`、`All Perfect`。

### 4.4 判定线透明度与音符（易错点）

**判定线的 alpha 不作用于其上的音符**——隐藏判定线时音符照常显示（三个参考实现一致，也被本项目的合成用例测试覆盖）。只有两种例外会影响音符：

- RPE：alpha 事件为**负数**时，隐藏判定线的同时隐藏该线所有音符（作者称这是废弃的非法功能，但仍然有效）；
- 官方/PEC：prpr 的 `pe_alpha_extension` 对负 alpha 的额外编码（`-1` 隐藏线与音符、`-2` 隐藏对侧音符、`-100..-1000` 控制音符提前出现拍数），v1 未实现。

### 4.5 父子判定线（对齐 Phira 实现）

RPE 的 `father` / `rotateWithFather` 按 **Phira/prpr 的实现**处理（`prpr/src/core/line.rs` 的 `fetch_rot` / `fetch_pos`，见 `docs/02 §3.2`）：

```
父线世界旋转  rot_p = 父线自身 rot + (父线.rotateWithFather ? 祖父线 rot : 0)     （递归）
子线世界旋转  rot_c = 子线自身 rot + (子线.rotateWithFather ? rot_p : 0)
子线世界位置  pos_c = pos_p + R(rot_p) · 子线自身偏移
```

要点：

- **偏移会被父线旋转**（即使子线不继承旋转）——这是 Phira 的行为，也是「子线以父线为原点」的正确含义；
- 偏移的旋转必须在**等尺度空间**里做：规范坐标的 x 是画面宽比例、y 是画面高比例，因此代码先按 `aspect = W/H` 把 x 折算成与 y 同尺度、旋转后再折回（`state.aspect`，渲染区域固定 16:9）；
- `rotateWithFather` 字段缺省时视为 `false`（Phira 的 `unwrap_or(false)`），兼容 163 以前版本；
- 父线可嵌套；Phira 对成环会直接报错拒绝谱面，本实现**降级**为「忽略该父线 + 解析告警」（越界、自引用同样处理）。

对应测试：父线旋转 90° 时子线局部 +0.1 屏宽偏移落到世界 (0.2, +0.1778 屏高)；`rotateWithFather = true/false/缺省` 三种旋转结果；成环与越界父线的降级。

### 5.5 已知问题与歧义

- **父线语义**：已按 Phira 实现（`pos = 父 pos + R(父 rot) × 偏移`，旋转由 `rotateWithFather` 决定，缺省 false）；Phichain 文档称 RPE 子线不继承旋转，与 Phira 不一致，本项目采用 **Phira** 口径。注意 `pos` 的旋转依赖画面宽高比（`state.aspect`，固定 16:9）。
- **音符宽度**：作为**可修改的默认值**处理，默认 **W/8（0.125 画面宽）**。对照：prpr ≈0.132 W、phi-chart-render ≈0.118 W（均为资源包口径）、仓库参考效果图实测 ≈0.17 W——三者不一致，故不写死。
- **判定线长度**：官方口径有多个（Lchzh 实测 5.76 H、Phira `lineLength` 默认 6.0、phi-chart-render 3 W、PEC 3.91 W）；v1 用 5.76 H。由于它们都远超屏宽，默认外观几乎看不出差异。
- **Phira 的 RPE 速度系数**（≈0.267）比文档语义（2/9）快约 20%：v1 采用文档语义（与样本数据吻合），若需与 Phira 逐帧对齐需换系数。
- **性能**：Canvas2D 后端每帧遍历全部音符（带可见性早退）；RPE 样本 1417 音符、8.1 万事件在本机无头测试中求值正常，但同屏数千音符 + 大量半透明贴图时建议换 WebGL2 批渲染。
- **音频同步**：v1 用 `AudioContext.currentTime` 作主时钟、`decodeAudioData` 整曲解码；官方「offset」语义按 `谱面时间 = 音乐时间 − offset` 实现，未做音频输出延迟校准。

关键断言：

- 官方样本：24 线 / 1156 音符 / 类型分布 616·324·180·36；**第 1 条线 280 个音符的 `height` 与谱面 `floorPosition` 全部一致**；`t=256, bpm=174 → 2.758621s`。
- RPE 样本：24 线 / 1417 音符 / 类型分布 tap 624·hold 165·flick 158·drag 470；`numOfNotes = 1252 = 1417 − Hold`；速度 `4495.5 → 999 Y/s`；`positionX 568.75 → 7.4897 X`。
- 事件层相加（合成用例）：135 + 270 = 405 单位 → 0.3 屏宽偏移；未给 alpha 事件的层贡献 0。
- 透明度语义：判定线 alpha = 0 时音符仍可见；RPE 负 alpha 则线与音符一起隐藏。
- 版本兼容：v1 的 `1000x+y`、v2 的「中心原点 0.1H」、v3473 与 v3 同构。
- 判定计分：两套样本跑完整时间轴后满分 1000000、最大连击 = 物量、无 NaN。
- 渲染路径：贴图全部就绪、`save/restore` 配平、可见音符确实被绘制、RPE 谱 + 713 个打击特效绘制无异常。
- **Hold 绘制几何**（对应真实反馈的两个问题）：长/极短 Hold 的各段目标高度之和都等于几何长度；头尾帽合计 < 30% 且绝对值固定（默认约 5–6px，不随长度放大）；极短 Hold 仍有中段；HL 贴图的本体宽度与普通贴图一致、光效单独绘制且不计入长度；`Tap` 与 `TapHL` 的本体宽度一致。

## 7. 作为制谱器「实时预览」的接入点

结论：**已预留**。内核与渲染已经拆成「模型 / 求值 / 投影 / 绘制」四层，且**求值是纯函数、时间和画面尺寸都由外部传入**，因此制谱器可以把它当一个「函数式预览内核」来调用，不需要改动渲染器内部。

### 7.1 现在就能直接调用的接口

```js
import { detectFormat, prepareChart } from './src/core/model.js';
import { parseOfficialChart } from './src/core/parse-official.js';
import { parseRpeChart } from './src/core/parse-rpe.js';
import { createState, evaluate, advanceJudging, resetState } from './src/core/state.js';
import { createCanvasRenderer } from './src/render/canvas2d.js';
import { createProjection, pickNote, pickLine } from './src/render/projection.js';

// 1) 谱面 -> 统一模型 -> 编译（事件关键帧、时间轴、heightAt、音符时间）
const chart = prepareChart(parseRpeChart(json));      // 或 parseOfficialChart

// 2) 每帧：时间由制谱器给（拖动进度条 / 播放音频 / 单帧步进都行）
const state = createState(chart, { aspect: 16 / 9 });
evaluate(state, editorTimeSeconds);                   // 纯计算：线变换、音符位置/透明度/可见性
advanceJudging(state, editorTimeSeconds);             // 预览用的自动游玩（编辑器可关掉：autoplay:false）

// 3) 绘制（也可以只在编辑器里画自己的叠加层）
renderer.draw(state, hitEffects);

// 4) 点选 / 叠加层：与渲染器共用同一套投影，绝不会与画面错位
const hit = renderer.pickNote(state, mouseX, mouseY, 24);   // -> { note, x, y, angle, distance }
const lineHit = renderer.pickLine(state, mouseX, mouseY, 10);
const proj = renderer.projection;                            // toScreenX/Y、toWorldX/Y、noteTransform、lineSegment
```

关键性质：

| 性质 | 说明 |
| --- | --- |
| 纯求值 | `evaluate(state, t)` 不依赖音频/时钟/画布尺寸，编辑器可以任意时刻求值（含负时间、单帧步进） |
| 尺寸无关 | 世界坐标是「画面中心比例」（x 宽比例、y 高比例），渲染器只负责最后一步换算；`projection` 同时提供正反变换 |
| 可关闭自动游玩 | `createState(chart, { autoplay: false })` 时不判 Perfect，编辑时可只看静态状态 |
| 模型可读写 | `prepareChart` 只做编译，原始 JSON 仍保留在 `line.raw` / `note.raw`；`chart.lines[].layers` 就是事件层本身，编辑器可直接增删改后再 `prepareChart` 一次 |
| 拾取已就绪 | `pickNote` / `pickLine` 与绘制共用 `projection.noteTransform`（同一条公式，不会出现「看到的和点到的不一致」） |

### 7.2 还缺什么（制谱器开工前要做的事）

| 缺口 | 现状 | 建议 |
| --- | --- | --- |
| **写回格式**（导出 official / RPE） | 只有解析，没有序列化 | 加 `src/core/serialize-official.js` / `serialize-rpe.js`；注意官方要求的哨兵与「事件列表不能为空 / 不能越过末尾」约束（`格式说明.md` §8），以及 RPE 的 Beat 有理数形式 |
| **增量重编译** | `prepareChart` 会重编译全部线（1417 音符 + 8.1 万事件的样本约 0.2–0.5 s） | 拆成 `compileLine(line)`，编辑器只重编译被改动的线；`heightAt` 也只对受影响的线重建 |
| **求值规模** | `evaluate` 每帧遍历全部音符（带可见性早退） | 编辑器同屏元素多时改为「按时间窗口 + 每线游标」索引（音符已按时间排序，可直接二分） |
| **叠加层绘制** | 只有单一 canvas 的绘制 | 加一个透明叠加 canvas（选中框、事件曲线、时间轴游标）或让 `draw()` 接受额外绘制回调 |
| **编辑命令层** | 无撤销/重做、无选区模型 | 引入命令栈（增删改音符/事件/判定线），每个命令只描述 diff，配合 7.2 的增量重编译 |
| **大谱面加载** | 40 MB JSON 在主线程 `JSON.parse`（约 0.3–1 s，界面会短暂卡住） | 解析放到 Web Worker，或先按需解析（例如只解析选中线的 notes）；编辑器应缓存模型而不是反复解析 |
| **音频编辑能力** | 播放/跳转/倍速已有；无波形、无节拍预览 | 用 `decodeAudioData` 的结果算波形峰值缓存；BPM 网格可直接用 `chart.timing.bpmList` + `timeline.secondToBeat` |
| **双向时钟** | 播放时钟在 `app/player.js`（音频为主） | 编辑器需要「编辑器时钟」为主：`evaluate(state, editorTime)` 已经支持，把 player 换成「音频跟随编辑器时间」即可（`player.seek(editorTime)`） |
| **WebGL2 后端** | Canvas2D | 同 7.2 的叠加层一起做：先抽象「绘制指令列表」，再加 `webgl2.js`（批处理 + 图集），Canvas2D 作为回退 |

### 7.3 最小集成示例（编辑器里嵌一个预览窗）

```js
// 初始化一次
const chart = prepareChart(parseRpeChart(json));
const state = createState(chart, { aspect: 16 / 9, autoplay: false });
const renderer = createCanvasRenderer(canvas, textures);
renderer.resize(width, height);
renderer.setBackground(bgImage);

// 编辑器拖动时间轴 / 改事件后调用
function refresh(timeSec) {
  evaluate(state, timeSec);     // 只重算状态
  renderer.draw(state, []);     // 再画一帧
}
// 鼠标交互
canvas.onclick = (e) => {
  const hit = renderer.pickNote(state, e.offsetX, e.offsetY, 24);
  if (hit) selectNote(hit.note);   // hit.note 就是编译后的音符对象（含 lineId / timeSec / height）
};
```

> 也就是说：制谱器的「预览窗」与「渲染器 app」共用同一套内核，差别只在**时间从哪来**、**是否自动判定**、**要不要额外绘制叠加层**这三件事。
